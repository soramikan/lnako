# ベンチマークv2と最初の改善

ベンチマークの実行方法、20ケースの入力と期待値は[`benchmarks/README.md`](../benchmarks/README.md)を参照してください。旧v1の5ケース比較は歴史的な記録として残し、起動・定数畳み込み・文字列構築方式の影響を明記しました。

## SSA検証のコンパイル時間

逐次加算を1,500行並べたソースを測定すると、SSAの支配関係検証で、各候補について全ブロックを先行ブロック候補として繰り返し検索していました。実際の先行ブロック一覧を一度生成し、それを使って支配集合の積を計算するように変更しました。ブロック処理順序、固定点への反復、到達不能ブロックの扱いは維持しています。支配関係の行列自体は引き続きブロック数の二乗のメモリを使い、先行ブロック一覧の分だけ追加メモリを使います。密に接続する巨大な制御フローのメモリ削減は今回の変更対象ではありません。

macOS arm64、Zig 0.16.0、LLVM 22.1.8、両コンパイラReleaseSafe、対象O1での結果です。各1回のwarmup後、順序を交互に変えて各3回測定しました。

| 対象 | 中央値 |
| --- | ---: |
| 変更前 `a7690d6` | 73.861秒 |
| 同じソースにSSA検証の変更のみを適用 | 10.517秒 |

このコンパイル負荷では約85.8%短縮しました。起動、解析、SSA検証・最適化、LLVM IR出力までの時間であり、リンクや生成プログラムの実行時間ではありません。生成したLLVM IRのSHA-256は変更前後で一致しました。開発作業中のローカル測定なので、全プログラム・全OSへ同じ改善率を一般化しません。

[生サンプルと入力・コンパイラのhash](../benchmarks/results/verifier-scaling-macos-arm64.json)を保存しています。比較対象は同じcommitから別ディレクトリへ展開して同じビルド条件で生成し、候補側のみ`src/ir/verifier.zig`を変更しました。入力生成は次のとおりです。

```python
from pathlib import Path
Path('.cache/benchmark-compile-large.nako3').write_text(
    'A=コマンドライン[0]\n' + '\n'.join('A=A+1' for _ in range(1500)) + '\nAを表示\n'
)
```

各コンパイラで次を実行し、プロセス開始から終了までを単調時計で測定します。`LNAKO_LLVM_DIR`は同じ固定toolchainを指定します。

```sh
/path/to/lnako build .cache/benchmark-compile-large.nako3 \
  -O1 --emit llvm-ir -o .cache/measurement.ll
```

継続測定では、実行負担を抑えた150行版を`compile-stress-medium`としてnormal/fullへ追加しました。分岐合流、後方辺、到達不能ブロックの単体テストと既存のSSA検証テストを併せて使います。

## 統合検証

- `zig build fmt-check`、`zig build test`（688件）に成功。
- 20ケースで固定公式処理系とinterpreterの出力、全20ケースのAOT O0、代表7ケースのO2を照合。
- 比較ランナーsmokeは19ケース・76測定行、コンパイル専用O3は1ケース・1測定行の結果検証に成功。
- ネイティブCLIはnormalを1サンプルへ上書きして全20ケース・58測定行を検証。これは正しさの検証であり、normalの性能評価値には使用しません。
- 従来v1結果の読み取り互換を維持。
