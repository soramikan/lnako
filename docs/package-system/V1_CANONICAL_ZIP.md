# v1 Canonical ZIP の受理範囲（O06 実装メモ）

対象は `nako-registry` の「パッケージ形式・レジストリ仕様 要件」§3.2 と
O06 の細則を、`src/package/v1_zip.zig` の `pack` / `verify` がどう実装して
いるかの記録である。正本仕様そのものを変更するものではない。仕様への反映が
必要なら統括が別途行う。

## 1. パスと EFS

- エントリ名は常に UTF-8 として検証し、`/` 区切り・相対パス・`.`/`..`
  セグメント禁止などの §3.2 の規則を適用する。
- General purpose bit 11（EFS）がある名前は UTF-8 として受理する。
- EFS がない名前は、すべてのバイトが ASCII（`0x00..0x7f`）の場合だけ受理
  する。標準 ZIP の CP437 と UTF-8 は ASCII の範囲で一致するため、Python の
  `zipfile` のように ASCII 名には EFS を立てない生成器の ZIP を、ほかの
  規則が成立するときに受理できる。
- EFS がなく非 ASCII バイトを含む名前は `error.AmbiguousPathEncoding` で
  拒否する。CP437 のバイト列を UTF-8 と誤認しないためである。

## 2. 順序・時刻・名前衝突

- エントリは生の UTF-8 バイト列の昇順に並ぶ。厳密な昇順でない場合は
  `error.NotSorted`、同一バイト列は `error.DuplicateEntry`。
- DOS 日時は中央ディレクトリと局所ヘッダの双方で
  `1980-01-01 00:00:00`（date `0x0021`、time `0`）を要求する。
- 大小文字衝突は `src/generated/unicode_case.zig` の
  `unicode_case.simpleFold` をコードポイントごとに適用したキーで検出する。
  ASCII だけでなく `Ä.txt` と `ä.txt` のような UTF-8 パスも衝突になる。
  Unicode 正規化（NFC/NFD）や ß→ss のような複数コードポイントへの完全
  case folding は行わない。これは「大文字小文字を無視した比較」を単純
  case folding として実装する明示的な範囲である。

## 3. ZIP64

次の構造を「妥当な ZIP64」として受理する。

- EOCD の件数・中央ディレクトリサイズ・位置がセンチネル
  （`0xFFFF` / `0xFFFFFFFF`）で、EOCD の直前に ZIP64 EOCD locator と
  ZIP64 EOCD record がある。
- 中央ディレクトリまたは局所ヘッダのサイズ・位置がセンチネルで、対応する
  ZIP64 extra field（ID `0x0001`）が必要な値だけを APPNOTE の順序
  （展開後サイズ、圧縮後サイズ、局所ヘッダ位置、disk 番号）で持つ。
- ZIP64 EOCD は単一 disk（disk 番号 0、total disks 1）で、record の
  終端が locator の直前、中央ディレクトリの終端が ZIP64 EOCD の直前と
  密に連続する。

次は「不正な ZIP64 サイズヘッダ」として拒否する。

- センチネルがあるのに ZIP64 extra / EOCD64 / locator がない。
- センチネルがないフィールドに ZIP64 extra が付いている、または値を
  読み切った後に余剰バイトがある。
- ZIP64 extra の重複、順序違反、値の不足。
- EOCD64 の record size・位置・disk 番号・件数の不整合。
- 上限（圧縮後 25 MiB、展開後 100 MiB、2,000 ファイル）を超える値。

上限が小さいため、実運用で ZIP64 を必要とする `.npkg` は通常作れない。
それでも構造として妥当な ZIP64 を受理するのは、他の生成器が常に
非 ZIP64 を選ぶとは限らないためである。

## 4. データ記述子

General purpose bit 3 を立てたエントリを受理する。局所ヘッダの CRC・
サイズは 0 または中央ディレクトリと一致する値とし、圧縮データ直後の
データ記述子を中央ディレクトリの CRC・圧縮後サイズ・展開後サイズと
照合する。

- 記述子の署名 `0x08074b50` は任意。
- サイズは中央ディレクトリが ZIP64 のサイズを使ったエントリでは 8 バイト、
  それ以外は 4 バイト。
- 記述子の終端は次の局所ヘッダまたは中央ディレクトリの開始位置と一致
  しなければならない。CRC・サイズの不一致は
  `error.DataDescriptorMismatch`。

## 5. 追加フィールド

- 追加フィールドは「ID（2 バイト）＋サイズ（2 バイト）＋データ」の
  ブロックとして長さの整合を検査する。途中で切れたブロックは
  `error.InvalidExtraField`。
- ID `0x0001`（ZIP64）だけを意味解釈する。重複は拒否する。
- それ以外の ID は安全な追加情報として読み飛ばし、パス・時刻・種別の
  判断には使わない。局所ヘッダと中央ディレクトリの双方で同じ規則とする。
- 中央ディレクトリの comment は引き続き非正規として拒否する。EOCD の
  comment は末尾と一致する範囲で読み飛ばす（既存挙動）。

## 6. サイズ上限

- 入力 ZIP の実バイト長が圧縮後上限を超えた時点で
  `error.CompressedSizeExceeded`。中央ディレクトリの圧縮後サイズ合計にも
  同じ上限を適用する。
- 展開は 16 KiB ずつ行い、展開後合計が上限を超えた時点で中断する。
- ファイル数は EOCD / ZIP64 EOCD の件数で先に検査する。

## 7. 対応テスト

`src/package/v1_zip_test.zig` の以下が、受理する正当例と拒否する不正例を
固定している。

- `標準ZIP: EFS未設定のASCIIパスを受理し、非ASCIIは拒否する`
- `Z-04 UTF-8パスの大小文字衝突も拒否する`
- `Z-04 UTF-8パスの大小文字衝突を読み込み時にも拒否する`
- `ZIP64: 妥当なEOCD64とZIP64 extraを受理する`
- `ZIP64: 不正なEOCD64とサイズヘッダを拒否する`
- `データ記述子付きの標準ZIPを受理し、不一致を拒否する`
- `安全な追加フィールドを受理し、壊れたブロックを拒否する`
- `圧縮後上限はZIP実バイト長にも適用する`

`src/package/v1_archive_test.zig` は `verify` の実バイト長上限、旧
METADATA の TOML キー判定、`Verified` の入力非依存、アーティファクト固有
命令の生成を固定する。
