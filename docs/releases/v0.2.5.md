# lnako v0.2.5 リリースノート

日本語プログラミング言語なでしこ3のネイティブコンパイラ `lnako` バージョン **v0.2.5** のリリースです。
本バージョンではパッケージ取り込み・npm ESM解決・依存同梱・静的レジストリ公開の機能を拡充し、opt-inのAOT compat-js（QuickJS連携）に双方向値変換・ホスト変数ブリッジ・`sys.__exec` 動的ディスパッチを接続しました。あわせて言語互換性・静的検査の不具合を修正し、正規表現・HTTP通信・フロントエンドのセキュリティを強化しました。

## 主な変更点（v0.2.4からの改善）

### 1. パッケージ取り込み・npm ESM解決と配布・公開機能の拡充

- **npm ESM解決と世代 `deps` への実体化**：
  - `nako.lock` の `npmInstances` を世代管理の `deps` ディレクトリへ実体化し、ロックファイルからオフラインで再構築できるようにしました（[#53](https://github.com/soramikan/lnako/issues/53), [#223](https://github.com/soramikan/lnako/pull/223), [#240](https://github.com/soramikan/lnako/pull/240)）。キャッシュが欠落している場合、`lnako sync` はオンライン時のみロック記録のURLからtarballを再取得してSHA-256を検証したうえで展開します（[#254](https://github.com/soramikan/lnako/pull/254)）。
  - `package.json` の本格パースと `exports` サブパス解決、および `exports` を持たないパッケージの `name/sub` 従来解決を実装し、bare importをコンパイル経路へ接続しました（[#54](https://github.com/soramikan/lnako/issues/54), [#225](https://github.com/soramikan/lnako/pull/225), [#232](https://github.com/soramikan/lnako/pull/232), [#249](https://github.com/soramikan/lnako/pull/249), [#279](https://github.com/soramikan/lnako/pull/279)）。あわせて `package_root` と入口のsymlink正規化、lockコンテキスト・importerスコープ別の複数バージョン絞り込み、ルート入口の遅延解決に対応しています（[#258](https://github.com/soramikan/lnako/pull/258), [#279](https://github.com/soramikan/lnako/pull/279)）。
  - npm ESMの実行は `--compat-js` 明示時のみ有効で、通常モードへJavaScriptランタイムは混入しません。Nodeのlifecycle scriptは対象外で、`node` 条件の非暗黙化など安全側の境界を維持しています。また、パッケージルートの `main` / `module` 解決では `.js` / `.mjs` を補完しますが、`exports` を持たないパッケージの `name/sub` 従来解決では拡張子補完を行いません。

- **パッケージ宣言命令の静的検査と `lnako check` 強化**：
  - パッケージが宣言する命令メタデータを意味解析へ接続し、`lnako check` で選択featureの共通・専用推移依存、OS条件の照合結果、名前空間エイリアス診断を表示できるようにしました（[#52](https://github.com/soramikan/lnako/issues/52), [#224](https://github.com/soramikan/lnako/pull/224), [#227](https://github.com/soramikan/lnako/pull/227), [#251](https://github.com/soramikan/lnako/pull/251)）。
  - `lnako check --load-plugins` で宣言命令メタデータとJS・ネイティブプラグインの実登録内容を照合するようにし、命令メタデータ静的検査の完了基準を満たしました（[#259](https://github.com/soramikan/lnako/pull/259)）。

- **`build --bundle-deps` による依存同梱とSBOM出力**：
  - `lnako build --bundle-deps` で実行ファイルの隣に `<出力名>.deps/` を生成し、依存パッケージのネイティブプラグインとソースを同梱できるようにしました（[#56](https://github.com/soramikan/lnako/issues/56), [#260](https://github.com/soramikan/lnako/pull/260)）。実行時ローダーは実行ファイル自身のパスをOS APIから取得して解決するため、生成物を別ディレクトリへ移動しても動作します。
  - ネイティブプラグインの推移的動的ライブラリ依存（Mach-O `LC_LOAD_DYLIB` / ELF `DT_NEEDED`）を検出してpayloadへ複製し、`bundle.json` への記録、短縮可能な場合のin-place書換、およびプラグイン読み込み前の先読みに対応しました（[#268](https://github.com/soramikan/lnako/pull/268), [#269](https://github.com/soramikan/lnako/pull/269), [#270](https://github.com/soramikan/lnako/pull/270)）。
  - `--sbom <path>` によるSPDX 2.3 JSON形式のライセンス一覧出力に対応しました（[#255](https://github.com/soramikan/lnako/pull/255), [#260](https://github.com/soramikan/lnako/pull/260)）。`--compat-js --backend aot --sbom <path>` で同梱npm・ESMパッケージのSBOMを出力できるほか、通常AOTでも `--bundle-deps --sbom <path>` で同梱依存パッケージのSBOMを出力できます。

- **`lnako package publish` と3 OS結合E2E・文書整備**：
  - `lnako package publish` に公開前検証（既定dry-run）、静的レジストリへの冪等なPUT、`index.json` への自動登録、version recordへの収録実装（source / native / ESM）記録を実装しました（[#57](https://github.com/soramikan/lnako/issues/57), [#252](https://github.com/soramikan/lnako/pull/252), [#273](https://github.com/soramikan/lnako/pull/273), [#274](https://github.com/soramikan/lnako/pull/274)）。中央の認証付きpublication APIは未実装のため、現行の公開先は静的レジストリです。
  - パッケージ取り込みのAOT（O0〜O3）3 OS検証、参照パッケージのpublish→取得E2E、plugin+npm結合E2E、および利用・公開・移行文書を整備しました（[#50](https://github.com/soramikan/lnako/issues/50), [#58](https://github.com/soramikan/lnako/issues/58), [#222](https://github.com/soramikan/lnako/pull/222), [#247](https://github.com/soramikan/lnako/pull/247), [#253](https://github.com/soramikan/lnako/pull/253), [#257](https://github.com/soramikan/lnako/pull/257)）。cnako/lnako共通fixtureも [#210](https://github.com/soramikan/lnako/issues/210) として追加しました（[#248](https://github.com/soramikan/lnako/pull/248)）。現時点ではテスト用アダプター経由の検証にとどまっており、上流cnakoの公開版で同じソースを受理する確認が条件として残っています（cnako本体側の接続は [#61](https://github.com/soramikan/lnako/issues/61) で追跡）。

### 2. AOT compat-js（QuickJS連携）とホスト・システム連携

- **opt-inランタイム分離と配布アーカイブ同梱**：
  - `lnako build --compat-js --backend aot` を明示的なopt-in経路として追加し、通常AOTランタイム（`liblnako_runtime.a` / `lnako_runtime.lib`）へQuickJSを混入させない別ランタイム（`liblnako_runtime_compat.a` / `lnako_runtime_compat.lib`）へ分離しました（[#55](https://github.com/soramikan/lnako/issues/55), [#235](https://github.com/soramikan/lnako/pull/235)）。配布アーカイブには両ランタイムを同梱しています。`build --compat-js` の既定バックエンドは従来どおり `embedded` です。

- **JS 4命令・ESMプラグイン命令のAOT実行と双方向値変換・GC連携**：
  - `JS実行`、`JS関数実行`、`JSオブジェクト取得`、`JSメソッド実行` のQuickJSブリッジ接続とAOT dispatch trace記録（`LNAKO_DISPATCH_TRACE`）、およびESMプラグイン命令のAOTコード生成・実行時呼び出しに対応しました（[#241](https://github.com/soramikan/lnako/pull/241), [#242](https://github.com/soramikan/lnako/pull/242), [#243](https://github.com/soramikan/lnako/pull/243), [#244](https://github.com/soramikan/lnako/pull/244), [#256](https://github.com/soramikan/lnako/pull/256), [#263](https://github.com/soramikan/lnako/pull/263), [#271](https://github.com/soramikan/lnako/pull/271), [#275](https://github.com/soramikan/lnako/pull/275)）。
  - ネストした配列・辞書・循環参照・疎配列やBigInt・ByteBuffer・JS関数値・Nakoコールバック関数の双方向変換と、`JS関数実行` のPromise戻り値awaitを実装しました（[#277](https://github.com/soramikan/lnako/pull/277), [#280](https://github.com/soramikan/lnako/pull/280)）。NakoからJSへ渡したコールバック関数は世代付きIDとインスタンス参照カウントで管理し、JS側の生存期間に連動してGC解放します（[#281](https://github.com/soramikan/lnako/pull/281)）。

- **1引数 `JSオブジェクト取得` とQuickJSホスト変数ブリッジ**：
  - `--compat-js` 時のみLLVMから動的変数フレームを出力する変数解決基盤を追加し、AOTでも1引数 `JSオブジェクト取得`（ローカルフレーム→動的グローバル→名前付き関数→システム定数の順で解決）を有効化しました（[#55](https://github.com/soramikan/lnako/issues/55), [#283](https://github.com/soramikan/lnako/pull/283)）。
  - QuickJSホスト変数ブリッジ（`sys.__getSysVar` / `sys.__findVar` / `sys.__setSysVar` / `sys.__getSore` / `sys.__setSore`）をAOTへ接続し、公式 `cnako3`・lnakoインタープリター・lnako AOTの3者一致検証を追加しました。

- **`sys.__exec` によるAOTシステム実行・ホスト連携**：
  - QuickJSから `sys.__exec`（`this.__exec` / `sys.__v0.__exec` を含む）経由でユーザー定義関数、組み込みコア命令、Node・非同期・簡易HTTPサーバ命令、ESM・ネイティブプラグイン命令を動的に呼び出せるようにしました（[#282](https://github.com/soramikan/lnako/issues/282), [#290](https://github.com/soramikan/lnako/pull/290)）。
  - 静的な命令一覧にタイマー等が現れない動的 `sys.__exec` 呼び出しでも終了前に保留中の非同期処理を実行するようにし、捕捉済み例外の再送出防止と `それ` の非破壊化をインタープリターの挙動へ揃えました。組み込み命令を呼び出す際は不足引数を命令ごとの最小必要数まで `undefined` で補完しますが、0引数・可変長出力・タイマー・低レイヤー命令など補完しない命令や、ユーザー定義関数・プラグイン命令には適用しません。

- **現時点の制約**：
  - Windows x86_64 のcompat AOTリンク向けにMSVC/UCRT互換shimを追加済みですが、CIでの実リンク・実行検証は未完了のため現行では未対応扱いです（[#280](https://github.com/soramikan/lnako/pull/280)）。Windowsで `--compat-js` を使う場合は `--backend embedded` または `lnako run --compat-js` を使用してください。
  - `JSオブジェクト取得`・`JSメソッド実行` のトップレベルおよびコンテナ内でのPromise・bytes受け渡し拒否など、意図的に維持している境界は [QuickJS互換モード](https://github.com/soramikan/lnako/blob/v0.2.5/docs/compatibility/COMPAT_JS.md) に記載しています。

### 3. 言語互換性・静的検査・ランタイムの不具合修正と性能改善

- **入れ子の名前付き関数のモジュール関数巻き上げ**：
  - 関数内で定義した名前付き関数（`●…とは`）を公式 `cnako3` v3.7.24と同様にモジュール単位の `funclist` へ事前登録し、関数本体の親スコープをモジュールスコープとして扱うように修正しました（[#195](https://github.com/soramikan/lnako/issues/195), [#289](https://github.com/soramikan/lnako/pull/289)）。トップレベルから入れ子関数を呼び出した際の `UnknownCommand` やAOTの異常終了、外側ローカル変数への誤束縛を解消し、同名関数の入れ子定義や同名テスト関数による上書きも防ぎました。

- **未定義の命令名呼び出しと不完全文 `そうでなければ` のコンパイル時拒否**：
  - 組み込み命令・ユーザー定義関数・取り込み済みシンボルに解決できない命令名呼び出しや不完全文 `そうでなければ` を実行時エラーにせず、`lnako check`・`run`・`build` のコンパイル時診断で拒否するようにしました（[#228](https://github.com/soramikan/lnako/issues/228), [#288](https://github.com/soramikan/lnako/pull/288)）。なお、呼び出し箇所の後方に同名グローバル変数代入があるケース（例：`XYZ(1)` の後方に `XYZ=1`）は、既存の後方変数参照設計への影響を避けるため未変更です。
  - 動的評価（`ナデシコ` / `ナデシコ続`）へ実行時登録済みのネイティブ・ESMプラグイン命令と `{関数}` 参照を引き継ぐように修正しました。あわせて複数ESMプラグインを取り込んだ際に無修飾命令が誤ったプラグインへ配送される不具合を解消し、静的命令キー抽出とフォールバック配送を安全側へ整えました（[#291](https://github.com/soramikan/lnako/pull/291)）。

- **AOTの `システム時間ミリ秒` のミリ秒精度修正**：
  - AOTの壁時計取得が秒値に1000を掛けていたため `システム時間ミリ秒` が常に1000の倍数になっていた不具合を修正し、3 OS共通で実時間ミリ秒精度を返すようにしました（[#229](https://github.com/soramikan/lnako/issues/229), [#285](https://github.com/soramikan/lnako/pull/285)）。

- **`一時フォルダ作成` の既定パス組み立てと空白・空環境変数判定の修正**：
  - 引数省略時や `undefined` / `null` / 空白のみ（全角空白などUnicode空白を含む）の指定時にカレントディレクトリへ `undefinedXXXXXX` を作成していた不具合を修正し、インタープリター・AOT双方でOS一時ディレクトリ配下に `nako-` 接頭辞で作成するようにしました（[#276](https://github.com/soramikan/lnako/issues/276), [#286](https://github.com/soramikan/lnako/pull/286)）。空文字列の `TMPDIR` / `TEMP` / `TMP` 環境変数も未設定扱いでフォールバックします。

- **バイト列の数値文字列キー代入修正・要素判定の統合・読み取り高速化**：
  - バイト列への数値文字列キー代入（例：`B["2"]=88`）がownプロパティを生成していた不具合を修正し、AOT・インタープリター双方でECMAScriptのTypedArray要素規則（`ToPropertyKey` → `ToNumber` 評価 → 有効添字判定）へ統一しました（[#233](https://github.com/soramikan/lnako/issues/233), [#287](https://github.com/soramikan/lnako/pull/287)）。右辺の `valueOf` 実行中にGC回収が起きて解放済みメモリを参照する不具合（UAF）もあわせて修正しています。
  - AOTで重複していたバイト列の要素判定を共有述語へ統合し（[#234](https://github.com/soramikan/lnako/issues/234), [#284](https://github.com/soramikan/lnako/pull/284)）、数値添字の読み取りはキー文字列を生成せず直接返すよう高速化しました（[#231](https://github.com/soramikan/lnako/pull/231)）。

### 4. セキュリティと堅牢性の強化

- **正規表現エンジンの作業量・入れ子上限**：
  - 量指定子の反復による過大な探索を開始位置あたり32,768単位の作業量上限で打ち切り、構文の入れ子深さにも128段の上限を設けました（[#218](https://github.com/soramikan/lnako/pull/218)）。超過時は回復可能なエラーとして返します。

- **HTTP通信と再帰処理の保護**：
  - 簡易HTTPサーバ（受信側）では1リクエストの不正入力によりプロセス全体が終了する経路を遮断し、静的配信でのrealpathによるdocroot封じ込め、要求スコープでのアップロード一時ファイル回収、および保留接続数の上限（16件）を実装しました（[#219](https://github.com/soramikan/lnako/pull/219), [#220](https://github.com/soramikan/lnako/pull/220)）。
  - HTTPクライアント（送信側）の `POSTフォーム送信` と `DISCORDファイル送信` では、multipart boundaryを要求ごとの乱数へ変更し、フィールド名・ファイル名のエスケープと不正文字・boundary混入の拒否を追加しました（[#220](https://github.com/soramikan/lnako/pull/220)）。
  - 値文字列化・JSON・TOML・Markdown変換・配列fill・AOT関数呼び出し深さへ再帰上限を導入し、インタープリターの呼び出しガードを実スタック消費量ベース（6 MiB）へ改めました。動的評価（`ナデシコ`）の保持プログラム数にも上限（256件）を設けています。

- **コンパイラフロントエンドとパッケージ展開境界の強化**：
  - 字句解析・構文変換の二次計算量経路を単一パスへ線形化し、AST走査とモジュール取り込み深さ（上限512段）の無制限再帰を解消しました。AOTの型付きローカル変数で未初期化 `alloca` が残る問題も関数入口での初期化により修正しています（[#221](https://github.com/soramikan/lnako/pull/221)）。
  - パッケージ取得・展開境界ではtar/gzip展開時の全消費バイト予算化とヘッダサイズ計算のオーバーフロー防止に加え、Gitツリー内の `.git` 別名・8.3表記パスの拒否を追加しました（[#220](https://github.com/soramikan/lnako/pull/220)）。

## インストール

### macOS：Homebrewでインストール（推奨）

```sh
brew tap soramikan/tap
brew install lnako
lnako --version
```

インストール後、`lnako run` ですぐにプログラムを実行できます。ネイティブ実行ファイルを作る場合は、初回に `lnako toolchain install` を実行してください。

### ファイルをダウンロードして使う

お使いのOS・CPUに合うファイルを次の表からダウンロードしてください。

- **standard**：プログラムの実行・構文チェックを始めたい方向けの軽量版です。後から `lnako toolchain install` でコンパイルに必要なLLVM/LLDを追加できます。
- **full**：LLVM/LLDを同梱しています。追加のダウンロードなしですぐにネイティブ実行ファイルを作成したい方はこちらを選んでください。

| OS・CPU | standard | full（LLVM/LLD同梱） |
| --- | --- | --- |
| macOS・Apple Silicon（arm64） | [lnako-0.2.5-macos-arm64.tar.gz](https://github.com/soramikan/lnako/releases/download/v0.2.5/lnako-0.2.5-macos-arm64.tar.gz) | [lnako-0.2.5-macos-arm64-full.tar.gz](https://github.com/soramikan/lnako/releases/download/v0.2.5/lnako-0.2.5-macos-arm64-full.tar.gz) |
| Linux・x86_64（GNU） | [lnako-0.2.5-linux-x64.tar.gz](https://github.com/soramikan/lnako/releases/download/v0.2.5/lnako-0.2.5-linux-x64.tar.gz) | [lnako-0.2.5-linux-x64-full.tar.gz](https://github.com/soramikan/lnako/releases/download/v0.2.5/lnako-0.2.5-linux-x64-full.tar.gz) |
| Windows・x86_64 | [lnako-0.2.5-windows-x64.zip](https://github.com/soramikan/lnako/releases/download/v0.2.5/lnako-0.2.5-windows-x64.zip) | [lnako-0.2.5-windows-x64-full.zip](https://github.com/soramikan/lnako/releases/download/v0.2.5/lnako-0.2.5-windows-x64-full.zip) |

展開後はフォルダー構成を保ったまま、`bin` フォルダーをPATHに追加してください。macOS版はDeveloper IDによるコード署名・Appleの公証に対応しています。

## はじめての実行

UTF-8で `hello.nako3` を作成します。

```nako3
「こんにちは、世界！」と表示する。
```

```sh
lnako check hello.nako3          # 構文・意味チェック
lnako run hello.nako3            # スクリプトとして直接実行
```

ネイティブ実行ファイルを作る場合：

```sh
# standard版・Homebrewでは初回のみ必要（full版では不要）
lnako toolchain install
lnako build hello.nako3 -o hello -O2
./hello
```

Windowsでは出力名を `hello.exe` にして、`.\hello.exe` で実行してください。詳しい導入手順は[使い始める](https://github.com/soramikan/lnako/blob/v0.2.5/docs/GETTING_STARTED.md)をご覧ください。

## その他の添付ファイル

通常のインストールでは、上の表のアーカイブだけで始められます。

- `*.sha256` / `SHA256SUMS`：ダウンロードしたファイルのチェックサム確認用。
- `*.spdx.json`：同梱ソフトウェアの構成情報（SBOM）。
- `Source code (zip / tar.gz)`：ソースからビルドする開発者向け。
