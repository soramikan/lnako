# 互換性quirksの書式

領域別文書へ項目を追加するときは、次の形を使います。

```text
### 境界の名前

- 公式実測・source根拠:
- lnakoの現在動作:
- 判定: 仕様 / 公式バグ候補 / 意図的制限 / 未実装
- 対象経路: Interpreter / AOT / QuickJS
- 差分テストID:
- TODO識別子:
```

## 判定の使い分け

- **仕様**: 固定した公式sourceと実測が一致し、互換対象として実装する境界。
- **公式バグ候補**: 公式実装または依存ライブラリの挙動が説明と食い違う、または入力に対して壊れた結果を返す境界。公式の結果を隠さず、利用者が依存しないよう明記する。
- **意図的制限**: 外部通信、外部実行ファイル、危険なOS操作など、lnakoが安全性・再現性のために差異を設ける境界。
- **未実装**: lnako側に残る差異。証拠や分類を完成扱いにしない。

実行結果の証拠ではない一般的な設計判断は、ここではなく [`COMPATIBILITY_EVIDENCE.md`](../COMPATIBILITY_EVIDENCE.md) または [`ARCHITECTURE.md`](../ARCHITECTURE.md) に記録します。
